# Contributing

Pull requests are welcome when they improve clarity, correctness, or operational safety.

## Before submitting

- run the relevant Go tests
- run formatters and linters
- keep the public contract and docs in sync
- document major decisions in the ADRs

## Style

- prefer boring, explicit code over clever abstractions
- keep platform concerns in shared packages
- keep business logic in the owning service
- do not leave placeholders or TODOs
