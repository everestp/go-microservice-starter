# Security Policy

This repository is a learning and starter template. It does not replace a vetted production security review.

## Core principles

- no secrets in git
- fail closed on invalid config
- use least privilege for database and messaging access
- verify signatures and tokens before trust
- isolate internal service traffic with certificates and identities

## Reporting a vulnerability

Open a private security advisory or contact the repository maintainers directly. Do not leak details through public issues.
